# RV32M 硬件乘除法扩展规格书与微架构对比讲义

> **适用范围**：本规格书定义 RISC-V 32 位整型乘除法扩展（RV32M Standard Extension for Integer Multiplication and Division）在 5 级流水线 CPU 中的硬件微架构设计、接口协议与方案对比。供工程实现、仿真验证与面试深挖学习。

---

## 1. RV32M 指令集规范与边界条件

RV32M 扩展共包含 8 条 32 位 R-Type 指令，固定编码如下：
- `opcode = 7'b0110011` (`OP`)
- `funct7 = 7'b0000001` (`MULDIV`)

### 1.1 指令清单与语义定义

| 指令 | funct3 | 汇编格式 | 操作数类型 (rs1 / rs2) | 运算行为与写回目标 (rd) | 典型应用场景 |
|:---|:---:|:---|:---:|:---|:---|
| **MUL** | `000` | `mul rd, rs1, rs2` | 有符号 / 有符号 | 取 $32 \times 32$ 积的低 32 位：$(rs1 \times rs2)[31:0]$（注：低 32 位结果在代数上与无符号乘法完全一致） | 通用乘法运算 |
| **MULH** | `001` | `mulh rd, rs1, rs2` | 有符号 / 有符号 | 取有符号积的高 32 位：$(rs1 \times rs2)[63:32]$ | 64 位大整数相乘高位获取、定点数定标截断 |
| **MULHSU** | `010` | `mulhsu rd, rs1, rs2` | 有符号 / 无符号 | 取有符号与无符号积的高 32 位 | 多精度大整数运算中的交叉项计算 |
| **MULHU** | `011` | `mulhu rd, rs1, rs2` | 无符号 / 无符号 | 取无符号积的高 32 位：$(rs1 \times rs2)[63:32]$ | 64 位无符号大整数高位获取、定点数无符号定标 |
| **DIV** | `100` | `div rd, rs1, rs2` | 有符号 / 有符号 | 有符号整型除法商：$rs1 / rs2$（向零舍入 Round-to-Zero） | 通用带符号整数除法 |
| **DIVU** | `101` | `divu rd, rs1, rs2` | 无符号 / 无符号 | 无符号整型除法商：$rs1 / rs2$（向下取整截断） | 通用无符号整数除法、指针/地址除法 |
| **REM** | `110` | `rem rd, rs1, rs2` | 有符号 / 有符号 | 有符号整型余数：$rs1 \% rs2$（余数符号严格与被除数 rs1 保持一致） | 带符号取模与哈希计算 |
| **REMU** | `111` | `remu rd, rs1, rs2` | 无符号 / 无符号 | 无符号整型余数：$rs1 \% rs2$ | 循环队列取模、无符号哈希分桶 |

> [!NOTE] 代数恒等式铁律
> RISC-V 规范强制要求：除除以 0 和溢出特殊情况外，在所有正常输入下，硬件必须严格满足以下代数恒等式：
> $$(rs1 / rs2) \times rs2 + (rs1 \% rs2) \equiv rs1$$
> 且有符号余数满足：当 $rs1 \% rs2 \neq 0$ 时，$\text{sign}(rs1 \% rs2) = \text{sign}(rs1)$。

### 1.2 RISC-V 官方标准边界条件与异常处理表

RISC-V 架构为了简化硬件逻辑并避免在除法异常时引入复杂的 Trap/中断上下文切换，**规定除法异常（除以 0、有符号溢出）不触发硬件 Trap**，而是直接由硬件静默返回明确规定的确定性默认值：

| 异常边界条件 | 被除数 rs1 ($x$) | 除数 rs2 ($y$) | DIV ($x / y$) | DIVU ($x / y$) | REM ($x \% y$) | REMU ($x \% y$) | 规范设计理由 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| **除以零 (Division by Zero)** | 任意值 $x$ | `0x00000000` ($0$) | `-1` (`0xFFFFFFFF`) | $2^{32}-1$ (`0xFFFFFFFF`) | $x$ | $x$ | 规避硬件 Trap 开销；软件可单指令 `beqz y, ...` 自行检查；返回全 1 可使多数未校验程序迅速暴露 |
| **有符号除法溢出 (Signed Overflow)** | `-2147483648` (`0x80000000`) | `-1` (`0xFFFFFFFF`) | `-2147483648` (`0x80000000`) | *不适用（无符号 $2^{31}/(2^{32}-1)=0$）* | `0` (`0x00000000`) | *不适用（无符号 $2^{31}\%(2^{32}-1)=2^{31}$）* | 二进制补码中 $-2^{31} / -1 = +2^{31}$ 超出 32 位有符号范围（最大 $2^{31}-1$），按两补码环形环绕保持符号不变，余数清零满足恒等式 |

## 2. 硬件微架构方案对比与选型（面试深挖重点）

乘除法器是处理器中除浮点单元（FPU）外算力密度最高、面积与时序权衡最为复杂的运算单元。

### 2.1 乘法器微架构对比

```
                ┌────────────────────────────────────────────────────────┐
                │                  乘法器常见硬件架构                    │
                └──────────────────────────┬─────────────────────────────┘
                                           │
         ┌─────────────────────────────────┼────────────────────────────────┐
         ▼                                 ▼                                ▼
【方案 1：移位加迭代乘法】        【方案 2：FPGA 硬核 DSP 映射】       【方案 3：Booth + Wallace Tree】
  - 纯 LUT 逻辑，面积极小          - 专用 APM/DSP48 切片，零 LUT 消耗   - ASIC 经典高性能阵列结构
  - 32 拍迭代，性能低              - 1~2 拍完成，极高 Fmax              - 纯组合或两级流水，面积大
```

| 方案 | 硬件实现原理 | 资源开销 (FPGA / ASIC) | 计算时延 (Latency) | 关键路径时序影响 (Fmax) | 适用场景与优缺点分析 |
|:---|:---|:---|:---:|:---|:---|
| **方案 1：32 拍移位加迭代乘法** | 维护 64 位累加器，每拍根据乘数最低位决定是否加被除数，随后右移 1 位，循环 32 拍 | **极小**：仅需约 64 个触发器与 1 个 32 位加法器 | 32 拍 | **优秀**：关键路径极短，单拍组合延时 $< 2\,\text{ns}$ | 适合极致低功耗、面积受限微控制器（如 Cortex-M0）。缺点是乘法吞吐极低，大幅拉低 DSP 密集型程序性能 |
| **方案 2：推断 FPGA 硬核 DSP（本设计采用）** | 使用 Verilog `*` 操作符，将操作数拓展至 33 位有符号数后直接相乘，综合工具自动映射至 FPGA 的 APM / DSP48 硬核 | **LUT 零开销**：消耗 2~4 个专用 DSP 切片 | 1~2 拍（本设计采用打 1 拍寄存输出） | **极优**：FPGA DSP 硬核支持 200~400 MHz，与 CPU 其它流水级隔离后完全不构成频率瓶颈 | FPGA 平台的最佳工程选择：充分利用片上闲置硬核资源，兼顾高主频与极低实现复杂度 |
| **方案 3：Radix-4 Booth 编码 + Wallace Tree 压缩** | 采用基 4 Booth 算法减少一半部分积（17 个），利用 Wallace 进位保留树（Carry-Save Adder, CSA）以 $O(\log n)$ 延时快速压缩，最后通过超前进位加法器（CLA）求和 | **巨大**：消耗大量 LUT 或标准逻辑门单元 | 1 拍（纯组合）或 2 拍（在 Wallace 树中打拍） | **中等/较差**：纯组合延时可达 10~15 ns，若强行在 EX 级单拍做完会严重恶化整核 Fmax | 工业级高性能 ASIC CPU（如 RV64 Rocket、BOOM、Cortex-A 系列）的主流标配，面积换速度 |

### 2.2 除法器微架构对比

```
                ┌────────────────────────────────────────────────────────┐
                │                  除法器常见硬件架构                    │
                └──────────────────────────┬─────────────────────────────┘
                                           │
         ┌─────────────────────────────────┼────────────────────────────────┐
         ▼                                 ▼                                ▼
【方案 1：恢复余数/非恢复余数】       【方案 2：Radix-4 SRT 除法】        【方案 3：Goldschmidt / 牛顿迭代】
  - 移位减循环 32 拍               - 每次迭代生成 2 位商 (16 拍)       - 倒数逼近乘法迭代 (3~5 次乘法)
  - 逻辑极其极简、鲁棒稳定         - 需冗余商查找表 (PD 图)           - 依赖高速乘法器，适合浮点/宽位
```

| 方案 | 硬件实现原理 | 迭代周期数 | 硬件复杂度与资源开销 | 关键路径组合时延 | 优劣分析与适用场景 |
|:---|:---|:---:|:---|:---|:---|
| **方案 1：恢复余数/试商移位除法（本设计采用）** | 每一拍将高位余数与被除数左移 1 位，尝试减去除数；若差为负则恢复（或不写回），商填 0；若差为正写回新余数，商填 1 | **32 拍**（特殊异常 1 拍） | **极小**：只需 1 个 32 位减法器、32 位余数寄存器、32 位商寄存器与 5 位计数器 | **极短**：单拍仅做 32 位无符号减法与 2 选 1 多路选择，时延 $< 2.5\,\text{ns}$ | 逻辑高内聚、零死锁、零状态歧义，极具教学与面试讲解价值；嵌入式内核的最普遍标配 |
| **方案 2：Radix-4 SRT 迭代除法** | 使用基 4 冗余数字系统（商数取值 $\{-2, -1, 0, 1, 2\}$），利用被除数与除数的高几位通过查表（P-D Diagram）预测 2 位商 | **16 拍** | **中等偏高**：需要 1 个生成 $-2D, -D, 0, D, 2D$ 的倍数发生器、CSA 减法树及查表逻辑 | **较长**：需查表并做进位保留运算，时序裕量低于恢复余数法 | 现代主流高性能处理器的标配除法器。以可控的面积增加使除法时延减半 |
| **方案 3：牛顿-拉夫逊 (Newton-Raphson) / Goldschmidt 乘法迭代** | 将除法转化为求倒数方程 $f(x) = \frac{1}{x} - D = 0$，通过 $x_{k+1} = x_k(2 - D x_k)$ 二次收敛迭代逼近，最后乘被除数得到商 | **10~15 拍**（取决于乘法器位宽与迭代次数） | **极高**：复用高速乘法器或单独实例化全精度定点乘法器，需要初始查找表与精度控制 | **较长**：受限于多级流水乘法器的往返时延与定点舍入截断逻辑 | 常见于 GPU 或高性能科学计算 FPU 中的浮点除法/开方单元。对定点整型存在不可恢复的精度误差边界修正难题 |

### 2.3 本系统最终选型决策与 Trade-offs 论证

本设计遵循 `AGENTS.md` 的**“低侵入性、高内聚、易读可讲”**铁律，做出如下微架构决策：

1. **乘法选型**：**基于 33 位符号扩展的可推断乘法 + 寄存器打 1 拍（共耗 2 拍，EX 级停顿 1 拍）**。
   - **为何不用纯组合单周期乘法？** 若在 EX 级单拍内完成 32x32 乘法，前推数据到达后经过乘法器，再送入分支/访存/写回多路选择器，会将整颗 CPU 的最大关键路径（Critical Path）拉长一倍以上，严重拖累 FPGA 板级最高主频。
   - **为何只停顿 1 拍？** 相比 32 拍移位加，1 拍停顿（2 周期）使 CoreMark 性能暴增，同时硬核 DSP 在打 1 拍后完全切断了前后级组合逻辑，使 CPU 能轻松跑上 FPGA 的时钟上限。
2. **除法选型**：**32 拍无符号试商减法状态机（Restoring Trial-Subtraction）**。
   - 包含除以 0、溢出快速旁路检测（1 拍即完成返回，零开销）；
   - 常规除法利用 32 拍标准状态机稳定迭代，单拍路径仅含 1 个 32 位减法器，面积极小且时序极其充裕。

## 3. 模块接口规范与流水线集成握手

### 3.1 模块端口信号清单 (`muldiv.v`)

```verilog
module muldiv (
    input  wire        clk,          // 系统主时钟 (上升沿有效)
    input  wire        rst_n,        // 同步复位，低电平有效
    input  wire        valid_i,      // EX 级当前存在有效的 M 扩展指令 (id_ex_valid && id_ex_muldiv_en)
    input  wire        flush_i,      // 流水线冲刷信号 (来自 hazard_unit，异常或跳转时清空计算状态机)
    input  wire [2:0]  funct3_i,     // 指令 funct3 字段 (000:MUL ~ 111:REMU)
    input  wire [31:0] op_a_i,       // EX 级经前推多路选择器后的操作数 A (对应 rs1)
    input  wire [31:0] op_b_i,       // EX 级经前推多路选择器后的操作数 B (对应 rs2)
    output wire        busy_o,       // 乘除法忙信号 (当拍正在运算且尚未完成，驱动流水线停顿)
    output reg         done_o,       // 计算完成脉冲 (当拍置 1，busy_o 归 0，计算结果 result_o 稳定有效)
    output reg  [31:0] result_o      // 32 位计算结果 (送往 EX/MEM 级间寄存器与 EX 级写回旁路)
);
```

### 3.2 硬件微架构状态机转移图

```mermaid
stateDiagram-v2
    [*] --> S_IDLE
    
    state S_IDLE {
        description: 空闲侦听状态。当 valid_i=1 时，busy_o 当拍置 1 触发流水线停顿。
    }

    state S_DIV {
        description: 32 拍除法迭代状态。cnt 从 0 累加至 31，每拍完成 1 位移位试减。
    }

    state S_DONE {
        description: 完成交付状态。当拍 done_o=1, busy_o=0，指令被顺利锁入 EX/MEM。
    }

    S_IDLE --> S_DONE : 乘法 (MUL*) 或除法特殊边界 (除以0/溢出)\n[耗费 1 拍]
    S_IDLE --> S_DIV  : 常规除法 (DIV*/REM*)\n[加载绝对值，cnt=0]
    S_DIV  --> S_DIV  : cnt < 31\n[cnt <= cnt + 1]
    S_DIV  --> S_DONE : cnt == 31\n[根据原符号取反并输出商/余数]
    S_DIV  --> S_IDLE : flush_i == 1\n[异常/跳转中断计算]
    S_DONE --> S_IDLE : 无条件转移 (下一拍 done_o 归 0)\n[若紧跟新 M 指令无缝启动]
```

### 3.3 流水线停顿与前推握手时序 (逐拍解析)

#### 场景 1：乘法指令执行时序 (1 拍停顿，共耗 2 拍)

```
时钟周期       │   Cycle 0    │   Cycle 1    │   Cycle 2
──────────────┼──────────────┼──────────────┼──────────────
指令所在阶段   │ MUL 进入 EX  │ MUL 留在 EX  │ MUL 进入 MEM
valid_i       │ ────── 1 ────┴────── 1 ────┴────── 0 ─────
done_o        │ ────── 0 ────┴────── 1 ────┴────── 0 ─────
busy_o        │ ────── 1 ────┴────── 0 ────┴────── 0 ─────
stall_id_ex   │ ────── 1 ────┴────── 0 ────┴────── 0 ─────
flush_ex_mem  │ ────── 1 ────┴────── 0 ────┴────── 0 ─────
result_o      │ ── 无效数据 ──┴── 稳定乘积 ──┴── (保持/默认)
EX/MEM 动作   │ 注入气泡(NOP)│ 锁存 result_o│ MEM 级正常流动
```

- **Cycle 0**：MUL 刚进入 EX 级。`valid_i = 1`, `done_o = 0`。组合逻辑当拍输出 `busy_o = 1`。
  - `hazard_unit` 捕获 `ex_muldiv_busy`，驱动 `stall_pc = 1`, `stall_if_id = 1`, `stall_id_ex = 1`, `flush_ex_mem = 1`。
  - `core.v` 的 BUG-003 防逃逸机制在 Cycle 0 上升沿把当拍的前推值 `ex_fwd_val_a/b` 锁存进 `id_ex_rs1/rs2_data`。
  - `muldiv` 模块在 Cycle 0 上升沿完成 33 位符号拓展乘法，将 66 位积或选通结果写入 `result_o`，并将状态置为 `S_DONE`，置 `done_o <= 1`。
- **Cycle 1**：MUL 仍在 EX 级。由于 `done_o = 1`，`busy_o` 自动降为 `0`！
  - 流水线停顿解除（`stall_id_ex = 0`, `flush_ex_mem = 0`）。
  - EX 级多路选择器选通 `ex_result = result_o`。在 Cycle 1 上升沿，`ex_result` 携带乘法运算结果顺利锁入 `ex_mem_alu_out`！
- **Cycle 2**：MUL 正式进入 MEM 级。`muldiv` 状态机在上升沿将 `done_o` 清零，恢复至 `S_IDLE`。
  - 若后续指令在 EX 级需要使用 MUL 的结果，`forwarding_unit` 通过标准的 `EX-EX` 前推网络，将 `ex_mem_alu_out` 前推给 EX 级，**无需流水线额外停顿**！

#### 场景 2：背靠背乘除法执行 (Back-to-Back 无气泡衔接)

若紧接在 MUL 之后的下一条指令仍是 MUL 或 DIV：
- 在 **Cycle 1 上升沿**，前一条 MUL 被锁入 `EX/MEM` 的同时，后一条 M 指令正好被锁入 `ID/EX` 并呈现于 EX 级；
- 在 **Cycle 2 开始**，`muldiv` 刚好完成复位回到 `S_IDLE`，同时捕捉到后一条指令的 `valid_i = 1`，当拍再次输出 `busy_o = 1` 启动下一轮计算；
- 状态机无任何多余的死锁周期，实现了极佳的背靠背吞吐率。
